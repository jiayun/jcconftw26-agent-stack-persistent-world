## 延遲與修正

初始設定未指定推理強度。取得的四個事件紀錄中，三個在約 45 秒後採作者文字備援；另一個約 39.9
秒完成。因此停止初次完整路線測試，沒有把備援結果算成模型演出成功。

對同一短篇演出提示做有上限的直接 API 對照：`reasoning_effort=none` 約 3.31 秒回傳，預設推理在 25 秒的測試上限內沒有完成。補上選填
`OPENAI_REASONING_EFFORT`，並將本機 `.env` 設為 `none`
；其他連線設定保留。未設定時不傳此參數，其他供應商可使用各自支援的值。[Ollama 參數說明](https://docs.ollama.com/api/openai-compatibility)

調整後的四條完整路線 54 回合，加上針對性測試 5 回合，共 59 個完成回合：

- 36 個回合實際呼叫模型，共 42 次模型請求。
- 模型回合中位耗時 2.774 秒，P95 為 6.513 秒，最長 6.785 秒。
- 0 次作者備援。上述統計不含初始失敗診斷與直接 API 對照。
- 服務紀錄合計 34,189 tokens；是 SDK 回報用量，不是帳單總量。
- 本輪真實模型自主工具呼叫為 0；不能據此宣稱雲端工具往返已驗收。受控模型工具往返測試另有通過。

## 仍需改善

1. **記憶回想答非所問**：輸入「我喜歡無糖茶。」後，再問「還記得我喜歡喝什麼嗎？」，模型改談北方旅行。保存層正確，演出沒有對準問題。程式的
   `narrate` 目前只收到已提交的摘要與記憶，沒有明確收到本回合原始問題，值得優先調整。
2. **場景與敘事不一致**：知識修復／出發的最後回合，結構化世界已正確出發，但演出重提河景與挑茶；部分回合增加沒有來源的往事。世界不變量通過不代表文字語意一致。
3. **角色語氣偏尖銳**：偏好測試出現「把你丟進河裡」等台詞；不符合溫和陪伴的預期，需調整角色提示與品質驗收。
4. **自由聊天限制偏嚴**：初次輸入「算了，先聊聊你今天的心情吧。」被要求改選事件行動。這是目前意圖解析提示的限制，並非模型連線失敗。
5. 設定 API 的隱私說明仍寫「傳送給 OpenAI」；使用相容供應商時文字應調整為「設定的模型服務」。
